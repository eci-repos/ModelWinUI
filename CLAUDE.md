# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**EDAM Studio** — a data-model (ERD) visualization tool. This repo is the WinUI 3 desktop app (`ModelWinUI`), which serves as a fast-prototyping sibling of a planned Uno Platform WebAssembly app. The graphics code is written to be portable: SkiaSharp runs on both WinUI and WebAssembly, so the Skia-based stack is the one intended to move to the WebAssembly sibling unchanged.

The project is early-stage: the graphics primitives (tables, orthogonal connectors, grips/handles) are the focus. Sample tables are drawn programmatically in `ModelPanelControl`; there is no file I/O or model-editing UI yet.

## Build & Run

The project targets `net10.0-windows10.0.19041.0` (WinUI 3 / Windows App SDK 2.4.0). It runs **unpackaged** (`<WindowsPackageType>None</WindowsPackageType>` in the csproj — required for direct exe launch; without it the WinAppSDK auto-initializer throws `COMException 0x80040154`). A platform must be specified — AnyCPU builds fail with "cannot be ProcessorArchitecture neutral".

```powershell
# Build (x64; also x86 / ARM64)
dotnet build src/Model.WinUI.Console/ModelWinUI.csproj -c Debug -p:Platform=x64

# Build the whole solution
dotnet build ModelWinUI.sln -p:Platform=x64

# Build a portable library alone (no WinUI dependencies)
dotnet build src/Model.Geometry/Model.Geometry.csproj -c Debug

# Run the unit tests (pure net10.0 — no WinUI needed)
dotnet test tests/ModelConsole.Tests/ModelConsole.Tests.csproj -c Debug
```

Run from Visual Studio using the launch profiles in `Properties/launchSettings.json`:
- **ModelWinUI (Unpackaged)** — `commandName: Project` (fastest for dev)
- **ModelWinUI (Package)** — `commandName: MsixPackage`

The unit-test project `tests/ModelConsole.Tests` (xUnit, net10.0) covers the portable libraries' pure modules: schema integrity, FK edge extraction, table layout, orthogonal routing, graph nodes, and model edits.

Known build warnings (not errors):
- `NETSDK1198` — the csproj sets `PublishProfile=win10-$(Platform).pubxml` but no `.pubxml` files exist in the repo. Harmless for `dotnet build`.

Key package versions: `Microsoft.WindowsAppSDK` 2.4.0, `SkiaSharp.Views.WinUI` 4.151.1, `CommunityToolkit.Mvvm` 8.4.2, `Microsoft.Windows.SDK.BuildTools` 10.0.28000.2526. Runtime identifiers are `win-x86;win-x64;win-arm64` (the `win10-*` RID prefix was removed in .NET 8+).

## Architecture

### UI control hierarchy

App (App.xaml.cs)
├── MainWindow (title "EDAM Studio")
│   ├── MenuBar (File → Open Model… / Open Sample / Model info)
│   └── ModelEditorControl            (Model.Controls.WinUI/Controls/ModelEditorControl.xaml)
│       ├── ModelExplorerControl      (left) — model structure tree
│       ├── ModelPanelControl         (center) — hosts the drawing Canvas
│       └── right column              — DiagnosticsLogControl (the log panel)
└── EntityDetailsWindow              (modeless, backlog 042) — hosts the
    EntityInspectorControl; opened by double-clicking a table/FK connector
    or File → Model info; its inspector is wired to the editor once
```

**All six controls live in the reusable `Model.Controls.WinUI` class library (backlog 034), not the app** — `src/Model.Controls.WinUI/Controls/`, alongside `SkiaCanvasView`, `DiagnosticsLogViewModel` (`ModelConsole.Controls.ViewModels`), the `ObservableObject` base (`ModelConsole.Controls.Helpers`), `DataElementName` (`ModelConsole.Controls.DataObjects`), and `IModelDataProvider`/`ModelDataProvider` (`ModelConsole.Controls.Services`). A host references the library, registers the DI contract (below), and drops `<ct:ModelEditorControl>`/`<ct:SkiaPanelControl>` into its own window. **The inspector is not hosted in the editor anymore (backlog 042)** — the right column is log-only; the reusable `EntityInspectorControl` lives in the host's modeless `EntityDetailsWindow`, wired to the editor via `ModelEditorControl.WireInspector`.

**Themed chrome (backlog 035):** every control header, panel toggle strip, zoom toolbar, the `MenuBar`, and the renderer bar are tinted pastel from one theme dictionary — `Model.Controls.WinUI/Themes/ControlTheme.xaml` (merged into `App.xaml` via `ResourceDictionary Source="ms-appx:///Model.Controls.WinUI/Themes/ControlTheme.xaml"` after `XamlControlsResources`; a referenced library's compiled XAML lands in the app package under its project name). Controls reference named **`{ThemeResource}`** keys (`ExplorerHeaderBackgroundBrush`/`InspectorHeaderBackgroundBrush`/`DiagnosticsHeaderBackgroundBrush` — all the zoom-toolbar gray `#F3F3F7` since backlog 042 (the per-panel pastels retired, so every banner reads as one strip), `EditorToggleStripBackgroundBrush`/`ModelToolbarBackgroundBrush`/`SkiaToolbarBackgroundBrush` soft grays, `MenuBarBackgroundBrush`/`RendererBarBackgroundBrush` warm gray, `ControlHeaderForegroundBrush`, `ControlBorderBrush`) — a host can shadow any key in its own merged dictionary to retune the palette. The tints stay out of the model's own color families (`#DCE9F7` entity blue / `#E2EFDA` reference green).

- `ModelPanelControl` creates a `GlContext` over its XAML `GlCanvas` and draws the sample model: a 50-table public-safety schema with every FK routed around the tables as an obstacle-avoiding `GlOrthoPath` connector (Canvas wrapped in a zoomable ScrollViewer). Connectors are anchored per-edge via `ConnectorAnchors`, routed sequentially via `SequentialRouter.RouteAll` (each routed edge becomes an obstacle for the next), and marked with 8 px `GlEllipse` endpoint circles. A zoom toolbar (fit button + slider + % box) drives the ScrollViewer's native zoom (`ChangeView`); Ctrl+0/1/Plus/Minus are wired as `KeyboardAccelerator`s. **The mouse wheel zooms around the cursor** instead of scrolling — `PointerWheelChanged` is handled on the `GlCanvas` (the ScrollViewer's content) and marked `e.Handled = true`, so it never bubbles to the ScrollViewer's scroll handler; `ApplyZoom` takes a **viewport-px anchor** (the cursor from `GetCurrentPoint(ModelScrollViewer)`) so the content point under the cursor stays fixed as the zoom changes. ScrollViewer offsets are **viewport px (zoom-applied)** — `ExtentWidth` grows with `ZoomFactor` — so the mapping is `content = (anchorPx + offset)/zoom`, `newOffset = content·zoom − anchorPx` (backlog 018: an earlier content-units model made the wheel zoom drift, the Fit button show blank, and pan run 1/zoom slow when zoomed out). **Wheel up zooms out, wheel down zooms in**, with a smooth delta-proportional step (`factor = Math.Pow(1.1, −delta/120)` ≈ 1.1× per notch, trackpad-friendly). The ScrollViewer's scroll bars are **Hidden** and its `ScrollMode` is **Disabled** (panning/zoom still work programmatically via `ChangeView` — the bars were confusing, and the WinUI 3 ScrollViewer scrolls on wheel even when the canvas marks the event handled, which at low zoom drifted the viewport to empty paper → blank page; `ScrollMode="Disabled"` kills the wheel-scroll while `ChangeView` is unaffected). The toolbar's **Fit button is labeled "Fit"** (icon + text). **Mouse panning (backlog 011):** left-drag on empty canvas space, middle-drag, or space+drag pans the drawing — `GlContext` raises `PanRequested(dx, dy)` (content-space delta from the pan start) and `ModelPanelControl` feeds `ChangeView(offset − delta·zoom, null, true)` (offsets are viewport px, so the content delta is scaled by the current zoom), so panning is 1:1 with the pointer at any zoom and never resets it. The `GlCanvas` has `Background="Transparent"` (a Panel with a null Background is not hit-testable in its empty areas — without it, empty-space presses never reach the pan gesture). The canvas is a large fixed "paper" (`CanvasSize = 20000`) with the content centered in it, so panning has room in all directions; the router region stays tight around the content (`_contentBounds` ± `ExtentMargin`) so the A* grid does not grow with the paper. `FitToWindow` fits to `_contentBounds` (all tables) with a **5 px margin**, not the canvas extent, centering via `(center)·fit − viewport/2` (viewport-px offsets); the app starts at 100% zoom showing the content's top-left. This is the entry point for exercising the graphics library. **Drawing-surface background (backlog 041):** the host grid (`DrawingSurface`, the row-1 Grid wrapping the ScrollViewer + hover overlay) paints the renderer-bar "Base:" color — the transparent canvas shows it through and the same color wraps the paper at low zoom; it defaults to white (`TablePalette.CanvasBackgroundHex`). **Table borders (backlog 041):** every table strokes the shared rest border (`TablePalette.BorderHex` `#5A5A5A` / `BorderWidth` 1.2) and **hovering a table** (tracked in `OnHoverChanged`, mutated live on the drawn `Table.Hovered` — no re-render) thickens it to the DodgerBlue accent (`HoveredBorderHex` `#1E90FF` / `HoveredBorderWidth` 2.4), the same accent the selection outline and connector emphasis use.
- **The canvas is editable (backlog 010 + 029):** the drawing is always *derived* from the model state — `ModelPanelControl` holds `_tables` (the `TableInfo` model) + `_layout` (current table positions) and `Render()` re-draws everything from that state. Dragging a table updates the layout and re-runs the pipeline (connectors follow); clicking a table or connector raises `EntitySelected`; **hovering a connector emphasizes it** — the line thickens to SlateBlue (3.5 px, the analogous violet neighbor of DodgerBlue, so it pops out of the blue connector tangle) and its start/end markers grow to 12 px (staying DodgerBlue) so the dependency's direction reads at a glance (the same emphasis the Skia renderer applies via its distance hit-test); `DeleteConnector` removes the FK `ConstraintInfo` from the model and re-renders so the remaining connectors regenerate as simple non-crossing routes. Double-clicking a table or connector opens the **modeless entity details window (backlog 042)** hosting the `EntityInspectorControl`, which shows the entity's details **read-only by default** — an **Edit/Done toggle** in the inspector's header reveals the full **edit surface (backlog 029)** (rename/add/remove entities and columns, edit column type/size, toggle PK, add/delete/edit FKs (target, cardinality, roles), edit description + key marking) and hides it again; the model-level provenance/metadata readout moves to **File → Model info** in the same window. The window's content is laid out as **bordered section cards** (entity summary, columns, foreign keys, properties) with **white/light-gray zebra column rows** and **PK/FK badge chips** tinted from the model's own color families — `InspectorAlternateBandBrush` is the zebra gray in `ControlTheme.xaml`. Single-click stays select-only (the DodgerBlue highlight) and, while the window is open, follows selection into it. Every edit mutates the live canonical model via the pure `ModelEdits` operations (below) → re-render (partial re-route where localized) → resolution issues surface via `FkEdgeExtractor` (R8), never a crash or a dangling connector. The details window's inspector builds its controls **gated by the 028 `NodeVerbs`** — a node only gets the edit controls its verbs allow. **Visibility projection (backlog 038):** `ModelPanelControl` holds the model's **one shared `EntityVisibility`** (`CurrentVisibility`, exposed via `SetVisibility(EntityVisibility)`) — `Render()` extracts all FK edges → `ModelProjection.Project` → draws only the visible tables/edges (layout runs over the visible subset, so hiding a group re-flows the rest); `SetVisibility` re-initializes the layout + re-renders. Explorer/inspector toggles mutate the shared instance through `ModelEditorControl.ApplyVisibility`, which re-renders the XAML path, re-syncs the explorer + inspector, and raises `VisibilityChanged` → `MainWindow` relays the same instance to the Skia renderer, so **both renderers draw the identical visible set** (parity, backlog 003). **Collapsed group boxes (backlog 039):** `ModelPanelControl` also holds the model's **one shared `GroupCollapseState`** (`CurrentCollapse`, exposed via `SetCollapse(GroupCollapseState)` — re-initializes layout + re-renders) — a collapsed group draws as a **UML package box** (`XamlGroupBox`, `ModelConsole.Graphics.Primitives.GroupBox`, name + `<<package>>` + count + per-group pastel from `GroupPalette.BoxHex`) that **replaces** its members in the layout grid, drawn set, and router-obstacle set; its external FKs aggregate to one connector per external target (count-labeled). Explorer `▣` collapse toggles and **clicking the box** (raises `GroupExpandRequested`) both mutate the shared instance through `ModelEditorControl.ApplyCollapse` (the 038 mirror) → `MainWindow` relays `CollapseChanged` → `SkiaEditor.SetCollapse`, so both renderers collapse the identical set. **Grouping themes (backlog 043):** `ModelPanelControl` also holds the model's **one shared theme name** (`_themeName`, default Tags; `CurrentThemeName` + `CurrentTheme` = `GroupingThemes.FromName(_themeName, _tables)`) — `SetTheme(string)` re-creates `_visibility = EntityVisibility.Create(_tables, CurrentTheme)`, resets `_collapse = new GroupCollapseState()`, re-initializes layout + re-renders, so the whole visibility/collapse/box pipeline re-derives over the new theme's groups. The explorer's `ThemeRequested`/`CollapseAllRequested` flow through `ModelEditorControl.ApplyTheme`/`ApplyCollapse` — `ApplyTheme` re-creates both shared instances and raises **`ThemeChanged` + `VisibilityChanged` + `CollapseChanged`** (the Skia renderer must get all three) → `MainWindow` relays `ThemeChanged` → `SkiaEditor.SetTheme`, so both renderers group + collapse the identical set.
- **Model explorer (backlog 004):** `ModelExplorerControl` is a collapsible **left panel** in `ModelEditorControl` (mirroring the right panel's 014 toggle) — a `TreeView` of the whole model: schema root → one node per table with a child node per column (name, type, PK/FK tags), plus a "Foreign Keys (N)" section via `FkEdgeExtractor.Extract` and a **Groups section (backlog 038)** — a checkbox per group (a group = a tag), a **"Show only:" `ComboBox`** (backlog 043 UX: picking a group narrows the drawing to only its members; "All groups" shows everything — the explicit focus entry, synced from the shared visibility, replacing the old Focus toggle that redefined what the checkboxes meant), and a **"Show all"** reset in the Groups header. Each group row also carries a right-aligned **`▣` collapse `ToggleButton` (backlog 039)** — "Collapse this group into a package box" — synced from the shared `GroupCollapseState` via `SetCollapse` and raising `GroupCollapseRequested` (the host's `ApplyCollapse` path re-renders both renderers). **Grouping themes (backlog 043):** the Groups panel is **hidden by default** and shown on request from a **"Groups ▸/▾" button at the far right of the "Model Explorer" header** (`BuildGroupsSection` never forces it open); inside it: a **"Group by:" `ComboBox`** (Tags / Schema / Kind / Connectivity), a per-row **count readout** `"(N tables, M FKs)"` (primary-group member count + internal FK count from `FkEdgeExtractor`), a labeled **"Package overview"** section with **"Collapse all" / "Expand all"**, and one-line hints explaining the checkbox/`▣`/overview controls. The section is rebuilt by `BuildGroupsSection()` from `GroupingThemes.FromName(_themeName, _tables).Groups(_tables)`; `SetTheme(string)` re-syncs it, and the ComboBox raises `ThemeRequested` while the buttons raise `CollapseAllRequested` (true = collapse all, false = expand all). Clicking a table node calls `ModelPanelControl.SelectTable` (DodgerBlue accent outline, hit-test transparent) and — while the details window is open — shows it there. `ModelPanelControl.SetModel` replaces the model (re-layout + re-render, raises `ModelChanged` → explorer refresh). `SetVisibility` re-syncs the checkbox states and **grays the tree nodes of hidden entities** (visibility never drops them from the tree, only from the drawing); each node's `Content` stays a plain string and the gray lands on the realized `TreeViewItem` container's `Foreground` (backlog 042 regression fix — a UIElement `Content` like a `TextBlock` makes WinUI 3's TreeView render the node type's name instead of the entity's).
- **File → Open Model… (backlog 004):** `MainWindow`'s `MenuBar` opens a JSON model file (`ModelFile.Load` — the database container form `{ dataSource, schemas: [{ name, tables }] }`, round-tripping columns + FK constraints; the legacy flat array of `TableInfo` stays readable) and feeds it to both renderers (`XamlEditor.SetModel` + `SkiaEditor.SetModel`; the Skia path clears its cached `ErdDiagram` and re-composes once on the next paint). The `FileOpenPicker` is initialized for the unpackaged app via `WinRT.Interop.WindowNative.GetWindowHandle` + `InitializeWithWindow.Initialize`; load errors surface in a `ContentDialog`.
- **File → Open Sample (backlog 005):** the same menu bar lists the **shipped sample models** — `Model.Data/Samples/PublicSafety.json` (50 tables / 74 FKs), `Library.json` (20 tables / 30 FKs), `Healthcare.json` (12 entities, grouped JSON) and `Enterprise.json` (27 tables / 31 FKs across **Sales / Inventory / Finance** with 3 cross-schema FKs — the multi-schema fixture the schema grouping theme needs to be visible, backlog 043), all in the **containerized form** (backlog 023 — schema declared once per group; the interpreter flattens it). The array samples are generated from the `PublicSafetySchema` / `LibrarySchema` / `EnterpriseSchema` fixtures via `ModelFile.ToJson`; the grouped `Healthcare.json` is a hand-authored fixture (`HealthcareSchema.Json`) loaded through the `Grouped` profile. All are copied into the app output `Samples/`. The submenu is built in code-behind from the `SampleModels` registry (`ModelConsole.ModelData`), so adding a sample to the registry adds it to the menu. Both `OpenModel_Click` and `OpenSample_Click` share a `LoadModel` helper that feeds both renderers; `SampleModelTests` validates the shipped files and keeps them in sync with the fixtures.
- `MainWindow` hosts **both renderers** with a slim renderer bar (backlog 003): two mutually-exclusive `ToggleButton`s — "XAML model" (default) and "Skia render" — swap `ModelEditorControl` and `SkiaPanelControl` in a shared grid. Both are XAML-instantiated (`Ioc.Default` is configured before `MainWindow` is created). The bar also carries the **Notation** toggle (backlog 040: ERD default / UML class-association view, relayed to both renderers) and the **"Base:" drop-down (backlog 041)** — the drawing-surface background color (White / Ivory / Mint / Light Gray presets + a **Custom…** WinUI color picker), applied live to **both renderers** via `ModelEditorControl.BackgroundColor` + `SkiaPanelControl.BackgroundColor` (the XAML path repaints the host grid; the Skia path clears each paint to it). **File → Export PlantUML…** writes a deterministic package diagram for the current theme/visibility/collapse viewpoint plus a full class diagram. MainWindow also owns the **modeless entity-details window (backlog 042)**: `XamlEditor.EntityDoubleClicked` opens the reused `EntityDetailsWindow` (created lazily on the first double-click; its inspector is wired once via `Attach(XamlEditor)`, and the reference is nulled on `Closed` — a closed WinUI 3 window cannot be re-activated, so the next double-click builds a fresh one), `EntitySelected` follows single-click selection into an open window, and **File → Model info** opens it in model mode (the provenance + metadata readout).
- `SkiaPanelControl` is the **Skia render path** (backlog 003): renders the full public-safety ERD (50 tables, 74 FKs). It composes the diagram **once** — `ErdComposer.Compose` (routing takes seconds, never per frame) — **off the UI thread** on first paint (a "Composing…" overlay shows progress; a stale-compose guard discards a compose that finished after a `SetModel`), caches the `ErdDiagram`, and replays tables + connectors per paint. **Zoom toolbar (backlog 015):** Fit button + zoom slider + % readout, defaulting to fit-to-window with a ~5 px margin (capped at 100%, recomputed on resize via `Translate`+`Scale` on `frame.Canvas`); the slider zooms 0.1–4.0. **The mouse wheel zooms around the cursor** (`PointerWheelChanged` on the `SKXamlCanvas`; a `_panX`/`_panY` offset in surface px keeps the content point under the cursor fixed — cursor DIPs are converted via `_dpiScale` = `e.Info.Width / ActualWidth`; **wheel up zooms out, wheel down zooms in**, with a smooth delta-proportional step `Math.Pow(1.1, −delta/120)` ≈ 1.1× per notch); the **Fit button (labeled "Fit")** resets the pan and re-enters fit mode. It has **drag-to-pan** (left-drag anywhere, middle-drag, or space+drag — the renderer is view-only, so a left-drag anywhere pans; DIP deltas scaled by `_dpiScale` keep the drawing 1:1 with the pointer at any zoom, and the pan composes with wheel-zoom/fit since `_panX`/`_panY` are the single pan source) and **connector hover-highlight** (no XAML hit-testing — hover is `RouteHitTest.Nearest`, a pure distance-to-polyline check with a constant on-screen 6 DIP radius scaled by `_dpiScale/_zoom`; the hovered route is drawn last, on top, as an emphasized `Connector` — a thicker **SlateBlue** line, the analogous violet neighbor of the DodgerBlue rest connectors, with larger DodgerBlue endpoint markers), and **table-hover border + base color (backlog 041)** — the paint clears to the renderer-bar "Base:" color (`BackgroundColor`, default `TablePalette.CanvasBackgroundHex` white; `GlFrame` gained an optional `backgroundColor` ctor param) and each table strokes the shared rest border, with the **hovered table** (a `HitTestTable` pointer→content hit-test on each paint) stroking the DodgerBlue accent — thicker (`HoveredBorderHex`/`HoveredBorderWidth`) — while under the pointer. It has no per-object drag/inspector; the XAML path keeps those. **Visibility (backlog 038):** `SetVisibility(EntityVisibility)` swaps the shared instance, clears the cached diagram, and re-composes once off-thread on the next paint — `ErdComposer.Compose` takes the optional visibility param and projects before measure/layout/routing, so the Skia path draws the same visible set as the XAML panel. **Collapse (backlog 039):** `SetCollapse(GroupCollapseState)` swaps the shared instance the same way — `ErdComposer.Compose` also takes the optional `collapse` param and collapses the visible projection into **boxes** (`Skia/Primitives/GroupBox.cs`) before measure/layout/routing, so the Skia path draws the same collapsed set as the XAML panel. **Grouping themes (backlog 043):** `SetTheme(string)` stores the theme name, clears the cached diagram, and re-composes once off-thread on the next paint — `ErdComposer.Compose` takes the optional `theme` param and derives the group universe/membership from it, so the Skia path groups + collapses the identical set as the XAML panel; the stale-compose guard also compares the theme name.

### Two parallel graphics stacks

The codebase contains two independent graphics libraries. Do not confuse them — they share class names (`GlObject`, `GlModel`, `Table`) under different namespaces.

1. **`ModelConsole.Graphics.GLibrary`** (active — WinUI XAML `Shape`-based rendering onto a `Canvas`) — since backlog 031 it lives in the reusable **`Model.Graphics.WinUI`** class library (`src/Model.Graphics.WinUI/`, `net10.0-windows`, WindowsAppSDK), which also ships the XAML factory contracts (`ModelConsole.Graphics.Services`). The app just references it; the stack's only app-bound dependencies (`ILogService`, `IDiagnosticWritter`/`DiagnosticsInfo`) come from `Model.Diagnostics`.
   - `GlContext` wraps the `Canvas` and owns all pointer handling (press/move/release/capture), selection, and the current grabber. It implements `IDiagnosticWritter` and logs through `ILogService` (resolved via the DI container). It raises `ShapeReleased` / `ShapeClicked` (drag vs click via a 2 px movement threshold) / **`ShapeDoubleClicked`** (backlog 042 — a second quick click, ≤ 500 ms, of the same object raises the double-click instead of `ShapeClicked`; the double-click is a distinct gesture and does not conflict with drag) and `PanRequested(dx, dy)` (pan gesture — left-drag on empty space, middle-drag, or space+drag; mouse only, delta in content units from the pan start) and `Reset()` clears interaction state before a full re-render. Cursor feedback (hand over empty space, move cursor while panning) goes through the `GlCanvas` subclass, which exposes the protected `UIElement.ProtectedCursor`.
   - `GlObject` (abstract) is the base for all drawable objects: `DeltaMove`, `Move`, `PointerEvent`, `Reshape`, `Selected`. Each object wraps a native XAML `Shape` (e.g. `GlRectangle` wraps a `Rectangle`, `GlOrthoPath` wraps a `Path`) and carries a `Data` payload (e.g. a connector's `FkRelation`). Every model-bearing drawable also exposes a typed graph node via `Node` (backlog 028) — the host consumes `obj.Node` (identity, live model object, hover summary, edit verbs) and never type-checks raw objects; drag/geometry still use the shape-level object.
   - Interaction model: `GlGrip` (resize nodes) and `GlHandle` (move) both implement `IGlGrabber`; `GlContext.SetPointerHandle` decides which one is active based on hit-testing `IGlGrip` nodes.
   - `GlOrtho/GlOrthoPath` draws orthogonal rounded-edge connector lines between shapes, with three grip nodes (start, end, middle) for reshaping.
   - `GlEllipse` is a small ellipse primitive — `Draw(context, centerX, centerY, diameter, fill)` positions it centered on a point (used for connector endpoint markers).
   - `Graphics/Primitives/Table.cs` renders a `TableInfo` as a rounded rectangle with a banner (`schema::table`), one `TableRowPanel` per column (constraint text, name, data type), and a closing **footer band** (backlog 036) that replaces the old dead tail. Its rows panel + banner are hit-test-transparent so the whole table drags. Banner, footer, and the alternating body-row stripes are all tinted by `TableKindClassifier` from the shared `TablePalette` (Model.Palette) — the single table-color source both renderers parse.
   - `Graphics/Primitives/GroupBox.cs` (backlog 039) is the collapsed group's **UML package box** — a `GlRectangle` subclass with a name compartment (16 Medium), a `<<package>>` + count compartment (13), a header `Border` tinted by `GroupPalette.BoxHex(group)` (rounded top), a plain body `Border` (rounded bottom + top hairline), `TablePalette` rest/hovered borders via `Hovered`, and a cached `GraphNodes.Group` node. Measured at construction (`ComputedWidth`/`ComputedHeight`, `GroupPalette` HeaderHeight 24 + BodyHeight 44, MinWidth 150); `DeltaMove` repositions the bands. Drawn through `IBoxFactory`/`BoxFactory` (`ModelConsole.Graphics.Services`).
   - `GlModel` implements `IGlModel` (`Items` list; `Add` adds and returns the instance). Resolved **transiently** from the DI container (a singleton would accumulate items across draws).

2. **`ModelConsole.Skia.GLibrary`** (portable — the Skia render path) — SkiaSharp rendering onto an `SKSurface`.
   - `GlFrame` wraps the `SKCanvas`, sets up default paints, and manages the coordinate system.
   - `Skia/Primitives/Table.cs` is the Skia counterpart of the XAML `Table`, with `ComputedWidth`/`ComputedHeight`/`GetRowCenterY` parity members (measure + anchor before drawing, backlog 003). `DrawBorders` composes its 180° rotation with the current canvas transform (`Save`/`Concat`/`Restore`) so a fit/zoom transform survives the draw (backlog 015). Since backlog 036 it closes with the shared footer band (same F as the XAML table), colors its banner and footer by `TableKindClassifier` from the shared `TablePalette`, and alternates two distinct kind-tinted row stripes (the old twin `#efefef` paints and the fixed light-green banner retired).
   - `Skia/Primitives/Connector.cs` (backlog 003) strokes a routed `Point2` polyline via `SKPathBuilder` + filled endpoint markers — the stack's first connector primitive. Null/empty points ⇒ no-op.
   - `Skia/Primitives/ErdComposer.cs` (backlog 003) is the reusable composition API: `Compose(tables, frame, options, visibility = null, collapse = null, theme = null)` → `ErdDiagram` (Layout/Edges/Routes/Issues) — measure probes → `EntityLayoutEngine` (Grid default plus connectivity-aware Serpentine/Circle/Cross layouts, backlog 044/045) → `FkEdgeExtractor` → `ModelProjection.Project` (backlog 038) → `GroupBoxAggregation.Build` per collapsed group (backlog 039, boxes **replace** their members in layout/routing; the theme param, backlog 043, drives the group universe/membership) → `ConnectorAnchors.Resolve`+`FanOut` → `SequentialRouter.RouteAll`. "Define and draw an ERD by writing code."
   - `Skia/Primitives/GroupBox.cs` (backlog 039) is the Skia collapsed group's **UML package box** — name band, `<<package>>` + count, per-group tint from `GroupPalette.BoxHex`, rounded, hit-testable (click-to-expand) and draggable like a table. Drawn through `ISkiaBoxFactory`/`SkiaBoxFactory` (`ModelConsole.Skia.Services`).
   - This is the stack intended for the Uno/WebAssembly sibling; keep it free of WinUI-specific dependencies.
   - **Lives in its own library `src/Model.Skia/`** (`net10.0`, `SkiaSharp` core) together with the `ISkiaTableFactory` / `ISkiaConnectorFactory` / `ISkiaBoxFactory` contracts; it references `Model.Graph`, `Model.Data`, and `Model.Geometry`. The XAML `Graphics` stack lives in `src/Model.Graphics.WinUI/` (backlog 031) — the reusable WinUI sibling.

#### The reusable library collection

The code lives in **eight layered, independently-reusable class libraries** under `src/` (backlogs 030 + 031 + 034 + 036). Each builds standalone (`dotnet build src/Model.X/Model.X.csproj -c Debug`); the app references the collection. Dependencies point only downward — no cycles:

```
src/
├── Model.Diagnostics/     net10.0, 0 packages            — logging subsystem + ILogService/LogService
├── Model.Geometry/        net10.0, 0 packages            — Point2/Rect2 + orthogonal routing + hit-test
├── Model.Data/            net10.0, JsonSchema.Net        — metadata model + interpretation + validation + fixtures + Samples/Schemas

├── Model.Graph/           net10.0                        — ERD logic + editing (→ Model.Data, Model.Geometry)

**Namespace identity (backlogs 032 + 031 + 034 + 036):** each library owns a single clean namespace and **no namespace is declared by two assemblies** — `ModelConsole.Geometry` (Model.Geometry), `ModelConsole.Graph` + `ModelConsole.Editing` (Model.Graph), `ModelConsole.Diagnostics` (Model.Diagnostics, home of `ILogService`/`LogService`), `ModelConsole.Palette` (Model.Palette — `TablePalette`, the shared table-appearance source: banner/footer/stripe hex + footer budget + the pinned-dark `TextHex` card text + rest/hovered table-border hex+widths + `CanvasBackgroundHex`), `ModelConsole.Skia.Services` (Model.Skia's factory contracts), `ModelConsole.Graphics.GLibrary` + `ModelConsole.Graphics.Services` (Model.Graphics.WinUI — the XAML stack **and** its `ITableFactory`/`IConnectorFactory`/`IRectangleFactory`), and `ModelConsole.Controls` + `.Controls.ViewModels`/`.Controls.Helpers`/`.Controls.DataObjects`/`.Controls.Services` (Model.Controls.WinUI — the controls, its view model/base/constants, and `IModelDataProvider`/`ModelDataProvider`). Each library also ships a README (`src/Model.X/README.md`) and NuGet packaging metadata (`Model.Console.<Layer>`, `Version 0.1.0`, README embedded via `PackageReadmeFile`) — `dotnet pack src/Model.X/Model.X.csproj` is clean.

### Data model (`Model.Data`)

Relational metadata classes: `CatalogInfo`, `TableInfo`, `ColumnInfo`, `ColumnList`, `ConstraintInfo`. `TableInfo` supports JSON round-tripping (`ToJson`, `ToJsonFile`, `FromJsonFile`); `ModelFile` loads/saves a whole model in the database **container form** `{ dataSource, schemas: [{ name, tables }] }` (schema declared once; `ToJson`/`LoadJson`/`Load` — the File → Open format, backlog 004 + 023, flat array still readable). **These POCOs live in the `Model.Data` library** (`src/Model.Data/`, namespace `Model.Data`). `ConstraintInfo` carries nullable FK parent references (`ReferencedTableName` / `ReferencedColumnName`; null column ⇒ resolve to the parent's PK). `TableKind` + `TableKindClassifier.Classify(TableInfo)` classify a table as an **entity** or a **reference-code** lookup (`Ref*` name prefix, or a small code/ID-key + `Description` table with ≤ 3 columns) — this drives the table's banner, footer, and body-row-stripe colors, sourced from the shared `Model.Palette` `TablePalette` (backlog 036). **`TableInfo.Tags` (backlog 037)** is the first *persisted* per-entity annotation — a serialized `List<string>` of UML-identifier-friendly labels (letters/digits/`_`/`-`, no leading digit), written only when present (`[JsonIgnore(WhenWritingNull)]` so untagged models stay byte-identical), round-tripped by both JSON formats + schemas, captured from source by the interpreter's `TagsField`, edited through the pure `ModelEdits.SetTableTags` (rejected names surface on the diagnostics log, never a crash), and shown in the explorer nodes + hover/readout — the deliberate **UML seam** the 038–040 grouping/visibility/export story builds on. Sample fixtures are the 50-table `PublicSafetySchema` (`ModelConsole.ModelData` in `src/Model.Data/ModelData/`), served to the controls via `IModelDataProvider.GetPublicSafetyTables()` — the old `GetPersonTable`/`GetPersonNameTable` fixtures were retired with the 034 extraction.

### Pure graph modules (`ModelConsole.Graph`)

Portable, deterministic, unit-tested geometry + routing across `Model.Geometry` and `Model.Graph` (no Windows.Foundation):
- `Geometry` — `Point2` / `Rect2` structs with strict-interior segment/rect tests.
- `RouteHitTest` — `Nearest(routes, point, maxDistance)`: the index of the route whose polyline is within the distance, else −1 (nearest wins) — the Skia renderer's hover hit-test, since it has no XAML hit-testing.
- `FkEdgeExtractor` — resolves `ConstraintInfo` FK references into `FkRelation` edges (parent PK default), reporting issues and skipping bad edges.
- `EntityLayout` + `EntityLayoutEngine` — name-driven entity placement into non-overlapping `Rect2` slots. Grid is the no-regression row-major default; Serpentine/Circle/Cross use a deterministic connectivity-aware order and projected edge-span optimizer before the router runs.
- `OrthogonalRouter` — A* grid pathfinding with obstacle inflation, outward stubs snapped to clear cells, collinear simplification, and an orthogonal Z-path fallback. Accepts `thinObstacles` (non-inflated, e.g. already-routed connectors) and checks segment crossings so a grid step cannot jump over a thin obstacle. **No connector crosses a table interior (backlog 012):** when the thin obstacles form a barrier that makes the grid unreachable, A* retries without them (crossing a connector is acceptable when the alternative is crossing a table); the Z fallback tries HV/VH variants and returns the first that avoids tables. `RouteBest` (backlog 033) is the sequential entry point: it routes **with and without** the thin walls and returns the crossing route only when avoiding it costs more than `RouterOptions.CrossingTolerance` (default 1.5) — crossing another connector is a cost, not a ban, so nearby tables never detour to the drawing's extremes; `PolylineLength` is the shared length helper. **Walkability-grid performance fix (2026-08-21):** A* precomputes a `WalkGrid` (blocked cells + blocked directed steps, using exactly the `Rect2.ContainsStrict`/`SegmentCrossesInterior` predicates the old per-expansion scans used) so the hot loop reads arrays instead of scanning the obstacle list — which grew to ~800 rects (every routed connector segment) by the end of a 50-table pass and made a collapse-all compose take **~63 s**. `Route` builds the base grid from the inflated tables **once** and both A* runs (with/without thin) clone it and stamp their thin connectors onto the copy; `SequentialRouter.RouteAll` on the 50-table sample now converges in **~1.9 s** regardless of `MaxExpansions`.
- `ConnectorAnchors` — `AnchorSide` + `Resolve` (departure side from child/parent relative position) + `FanOut` (offset shared-column anchors perpendicular to the side).
- `SequentialRouter` — `RouteAll` routes edges in fixed order via `RouteBest`, feeding each **chosen** polyline back as a thin obstacle so later edges avoid crossing it when that is cheap (and cross it when avoiding is absurdly expensive, backlog 033).
- `GroupingTheme` + `GroupingThemes` — the grouping-theme abstraction (backlog 043): a `GroupingTheme` maps a `TableInfo` to its group(s) — `PrimaryGroupOf(table)` (owning group — collapse/box membership) + `GroupsOf(table)` (every group — visibility membership) + `Groups(tables)` (ordered-distinct Ordinal universe, drops blanks). `GroupingThemes` is the static registry: **Tags** (primary = first non-blank tag, all = raw `table.Tags` — the authored theme, byte-identical to pre-043), **Schema** (primary = all = `table.SchemaName` — zero-authoring for multi-schema models), **Kind** (entity vs reference-code via `TableKindClassifier.Classify`), and **Connectivity(tables)** (union-find over `FkEdgeExtractor.Extract` edges; each table maps to its component, the group name is the **lexicographically-smallest table name** in the component — deterministic, not the union-find root; ≥ 2-table components become groups, singletons stay ungrouped → always visible per the composition rule). `FromName(name, tables)` round-trips the built-ins and falls back to Tags for unknown names. **The theme flows as a *name* (string)** — the concrete `GroupingTheme` is derived from `tables + name` at each use site, so a model change re-derives the connectivity theme automatically (never a stale instance).
- `EntityVisibility` + `ModelProjection` — the visibility layer (backlog 038): `EntityVisibility` is the pure composition rule (draw entity E iff **not pinned-hide** AND ( **pinned-show** OR **belongs to ≥ 1 visible group** OR **belongs to no group** )) with per-entity pins, per-group toggles (a group = a `TableInfo.Tags` value), and `SetFocus`/`ShowAll`; `EntityVisibility.Create(tables, theme = null)` derives the group universe from `theme.Groups(tables)` and `IsVisible` tests membership via `theme.GroupsOf(table)` — theme-aware since backlog 043, tag theme = the pre-043 default. `ModelProjection.Project(tables, edges, visibility)` → `(visibleTables, visibleEdges)` filters tables by the rule and `FkRelation` edges to those whose **both** endpoints are visible, preserving order and never mutating inputs (null visibility = everything). It runs **after** `FkEdgeExtractor` on the full model so unresolved-FK diagnostics (R8) surface even for hidden edges. **One shared instance** per model drives both renderers (see the editor wiring below); the visible projection is the UML package-diagram **viewpoint** (backlog 040).
- `GroupCollapseState` + `GroupBoxAggregation` — the collapse layer (backlog 039): `GroupCollapseState` is the pure collapsed-set rule (`SetCollapsed`/`ExpandAll`/`IsCollapsed`, per-group, default all-expanded). `GroupBoxAggregation.Build(tables, edges, group, collapsedSet, theme = null)` → model `GroupBox` (Group/Members/ExternalEdges/MemberCount) + `GroupBoxEdge` (TargetTable/TargetGroup, Outbound, Count, Sample, Label): members = primary-group tables (an entity's **primary group = its first tag** under the tag theme, `theme.PrimaryGroupOf` since backlog 043; in its other groups it appears only as a reference **stub** — the UML owning-package rule); external edges = those with exactly one endpoint in the box, **deduplicated per external target** (a collapsed target merges under its box; a collapsed target group inverts to a box→box edge); both-endpoints-outside ignored. `BoxKey(group)` → `"group::"+group`, the shared layout key — the box **replaces** its members in the layout grid, drawn set, and router-obstacle set, so a collapsed group is **one rect** and routing runs over box-level edges (the 2000-table win). **One shared instance** per model drives both renderers (the `CurrentCollapse` wiring below); the collapsed box is, by construction, a **UML package node** (backlog 040).
- `DiagramNotation`, `UmlProfile`, and `UmlPlantEmitter` — the UML view/export layer (backlog 040). **UML is derived, never canonical:** the ERD model stays the single source of truth and the model file gains no UML-only structure. Mapping: `TableInfo` → UML class named `Schema::Table`; `ColumnInfo` → public attribute `name: type(size)` with `{PK}`/`{FK}` tags; `ConstraintInfo`/`FkRelation` → directed association with child-side multiplicity from `MinCardinality`/`MaxCardinality` and roles from `ChildRole`/`ParentRole`; `TableInfo.Tags`/`GroupingTheme` → packages; `TableKindClassifier` → `<<entity>>`/`<<reference>>` stereotypes; `EntityVisibility` + `GroupCollapseState` → the package-diagram viewpoint. `UmlPlantEmitter.EmitClassDiagram` and `EmitPackageDiagram` are pure deterministic PlantUML emitters (package diagram honors the current theme/visibility/collapse state; class diagram emits the full class/association view).
- `GraphNode` + `HoverSummary` — the portable node surface (backlog 028): `IGraphNode` (kind/identity/live model object/summary/edit verbs), the immutable `NodeVerbs` presets, and the `GraphNodes` factory (null for null inputs). Node summaries delegate to `HoverSummary` (`ForTable`/`ForColumn`/`ForConnector`/`ForGroup`) so hover, inspector, and node never drift (the 022 discipline). The XAML `GlObject.Node` overrides build these nodes over their live `Data` payloads. `NodeVerbs.Entity` carries `CanToggleVisibility` (backlog 038) — the inspector's Show/Hide pin verb gate.
- `ModelConsole.Editing.ModelEdits` — the pure edit operations (backlog 029): atomic, invariant-preserving mutations over the canonical model. `RenameTable`/`RenameColumn` **cascade** across referencing FKs; `SetKey`/`AddForeignKey`/`RemoveForeignKey` recompute the column's `IsKey`/`IsForeignKey` from `Constraints` after add/remove; `AddColumn`/`RemoveColumn`/`SetColumnType`/`SetDescription`/`SetTableTags`/`EditForeignKeyTarget`/`SetCardinality`/`SetRoles`/`RemoveTable` cover the rest (`SetTableTags` normalizes — trim/dedupe/drop blanks — enforces UML-identifier hygiene via `IsValidTagName`, and returns rejected names separately so the inspector can log them). The inspector and `ModelPanelControl` call these (never hand-mutate), then re-render; a broken edit surfaces as a resolution issue through `FkEdgeExtractor` — never a crash.

These are pure static library calls — the app calls them directly (no DI registration). The 50-table fixture lives in `ModelConsole.ModelData.PublicSafetySchema` (`src/Model.Data/ModelData/`): 50 tables, 74 FK edges across the public-safety / criminal-justice domain.

### Diagnostics (`Model.Diagnostics`)

A logging subsystem ported from the author's earlier framework, extracted into the `Model.Diagnostics` library (`src/Model.Diagnostics/`, backlog 030; namespace `ModelConsole.Diagnostics`). The key wiring:
- `ResultLog.DefaultLog` is the process-wide log; `ResultLog.LogMessageHandler` is a static event.
- `DiagnosticsLogViewModel` subscribes through `ILogService.LogMessageHandler` (the DI wrapper that bridges the static event) and appends `IMessageLogEntry` items to an `ObservableCollection` bound by `DiagnosticsLogControl`.
- `GlContext.WriteMessage` is the path graphics code uses to log. `Log` (file/event-log writer) is largely inert here (`EVENT_LOG_SUPPORT` is not defined, so `Log.Write` returns false).

### MVVM

`CommunityToolkit.Mvvm` is referenced; `ObservableObject` (a hand-rolled base, `ModelConsole.Controls.Helpers`) and `DiagnosticsLogViewModel` (`ModelConsole.Controls.ViewModels`) both live in `Model.Controls.WinUI` (backlog 034). `DiagnosticsLogViewModel` is still the only view model.

### Dependency injection

**Dependency injection is the main mechanism for exposing functionality (services) and components (controls + graphics primitives).** The composition root is `App.ConfigureServices()` (`Microsoft.Extensions.DependencyInjection` 10.0.10). It runs **before** `MainWindow` is created and bridges to CommunityToolkit.Mvvm via `Ioc.Default.ConfigureServices(Services)`.

- **Resolution rules:** `Ioc.Default.GetRequiredService<T>()` is the **only sanctioned service-locator point**, and only for **XAML-instantiated controls** (they have no parameterized ctor). Code-created objects use **constructor injection**.
- **Service layer:** services are wired across the libraries by namespace (backlogs 032 + 031 + 034 — no namespace is declared by two assemblies) — `ILogService`/`LogService` in `ModelConsole.Diagnostics` (Model.Diagnostics; wraps `ResultLog.DefaultLog`, bridges the static event), `ISkiaTableFactory`/`ISkiaConnectorFactory`/`ISkiaBoxFactory` in `ModelConsole.Skia.Services` (Model.Skia, the box factory backlog 039), the XAML `ITableFactory`/`IConnectorFactory`/`IRectangleFactory`/`IBoxFactory` in `ModelConsole.Graphics.Services` (Model.Graphics.WinUI, the box factory backlog 039), and `IModelDataProvider`/`ModelDataProvider` (sample fixtures) in `ModelConsole.Controls.Services` (Model.Controls.WinUI, backlog 034) — the app registers the types but no longer declares them. A host must register the same set (the library README lists the 11 registrations).
- **Lifetimes:** stateless services + factories are **singletons**; `IGlModel` is **transient**; `DiagnosticsLogViewModel` and `LogService` must be singletons (transients double-wire the static log event and leak subscriptions).
- **Intended behavior change:** `GlContext.WriteMessage` now logs through `ILogService` — "GL Context Ready." actually reaches the log panel.

## Conventions

- Namespaces are `ModelConsole.*` (root namespace is `ModelWinUI` only for `App`/`MainWindow`).
- Graphics classes use the `Gl` prefix (`GlContext`, `GlRectangle`, `GlOrthoPath`).
- Code style is the author's: 3-space indentation in the graphics/data code, XML doc comments on most members, `m_` prefix on private fields.
- The `Skia` stack and the `Graphics` stack are meant to stay in sync conceptually; when adding a primitive, consider whether it needs a counterpart in both.
